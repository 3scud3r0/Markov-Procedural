Markov usa a sintaxe de Python e acrescenta operações procedurais para geometria, regras, ruído, textos, dados e animação.

Escreva funções, classes, algoritmos, condições e laços. O Studio compila e executa o programa em Python real dentro de um Worker. Você não precisa escolher um gerador pronto nem escrever uma receita JSON.

A programação é de propósito geral dentro do runtime Python disponível. O navegador não oferece acesso irrestrito ao sistema operacional ou compiladores nativos C/C++/Rust. Os exportadores existentes continuam tendo seu próprio subconjunto de IR.

01 / Primeiro programa

count = param("count", 8, min=1, max=30)

for i in range(count):
    sphere(radius=0.3,
           position=[i - count / 2, 1, 0],
           color="#d6ec9f")

print(f"Criei {count} objetos.")
emit("data.json", {"count": count})

Ctrl + Enter executa. Parar termina o Worker sem descartar o código. O console mostra stdout e os erros com arquivo e linha. Para um programa sem geometria, use o console e a aba Saídas.

node.translate(x=2).rotate(y=0.5).resize(1.5)

O Studio usa Babylon.js quando há WebGL. Sem WebGL, a mesma cena é projetada com Canvas 2D na CPU, com iluminação simplificada. Seleção e transformações continuam funcionando.

04 / Regras e parâmetros

@rule
def ring(count, radius):
    for i in range(count):
        angle = i * TAU / count
        sphere(radius=0.2,
               position=[cos(angle)*radius, 1,
                         sin(angle)*radius])

count = param("count", 16, min=4, max=50, step=1)
ring(count, 4)

@rule marca uma função reutilizável. param() declara controles no inspector e retorna seus valores. Não substituem funções e variáveis Python: fazem parte delas.

05 / Estado, animação e teclado

player = sphere(position=[0, 1, 0])

def update(t, dt):
    if "ArrowRight" in keys:
        player.position[0] += dt * 3
    player.position[1] = 1 + sin(t) * 0.25

Clique em Iniciar animação e dê foco à cena para usar o teclado. O callback preserva o estado entre frames; t e dt estão em segundos. keys contém as teclas pressionadas; mouse contém coordenadas da área de visualização e o estado de clique.

06 / Texto, dados e saídas

import json
from collections import Counter

frequencies = dict(Counter("procedural"))
print(frequencies)
emit("frequencies.json", frequencies)
emit("hello.txt", "Olá, mundo procedural!")

text = grammar({"start": ["Um mundo novo", "Uma nova regra"]})
emit("story.txt", text)

emit() aceita texto, objetos serializáveis e bytes. Arquivos escritos com open() no diretório virtual também são coletados ao fim da execução inicial. Escolha a saída na aba Saídas para ler e baixar.

# Gerar fontes usando a IR numérica existente:
generate("program", {"functions": 4},
         targets=["python", "c", "cpp", "rust", "sql"])

Este último comando exporta um programa da IR numérica. Não converte qualquer programa Python para todos os destinos e não executa compiladores nativos no Pages.

07 / Organize seu próprio projeto

Crie helpers.mp no explorador. Ele pode conter funções e classes e acessar as mesmas APIs. Importe pelo nome do módulo:

# helpers.mp
@rule
def create_point(x):
    return sphere(position=[x, 1, 0])

# main.mp
from helpers import create_point
create_point(2)

Salvar projeto baixa um JSON com código, parâmetros e edições da cena. Abrir restaura esse estado. O navegador guarda o último projeto e projetos recentes localmente. Compartilhar cria um link com o código; o destinatário decide quando executar.

08 / Um contrato claro

Projetos: 50 arquivos, até 2 MB de fontes no total. Cenas: 5.000 objetos, com orçamento adicional para malhas. Console: 100.000 caracteres. A execução inicial tem orçamento cooperativo de 8 segundos; o Studio encerra Workers que ultrapassam 20 segundos. É possível parar manualmente a qualquer momento durante a execução.

O filesystem é virtual no navegador. Imports dependem dos pacotes disponíveis no Pyodide. input() não oferece um terminal interativo; use parâmetros e eventos. O CLI executa com permissões locais e deve receber código confiável.

Leia a especificação completa da 1.0 para formatos, limites e critérios de aceite. Funcionalidades futuras, como glTF, colaboração e ferramentas de parser genérico, não são apresentadas como disponíveis.
